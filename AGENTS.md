# AGENTS.md — trust-LiMe

TRUST-LiMe is a **baltik application**: a C++ module built on top of the CEA
[TRUST](https://github.com/cea-trust-platform) kernel. It adds a magnetic-field
convection–diffusion equation on top of the existing thermohydraulics, to model
coupled MHD. Kernel sources live in a sibling checkout (`../trust-code`); this
repository only contains the module.

## Repository layout

| Path | Purpose |
|---|---|
| `src/` | Module sources: `Pb_MHD.{h,cpp}`, `Convection_Diffusion_Magnetic_field.{h,cpp}` |
| `build/` | Generated by `./configure` (symlinks to `src/`, CMake files). Do not hand-edit. |
| `share/Validation/Rapports_automatiques/` | Validation notebooks + `jdd.data` cases |
| `docs/` | Doxygen documentation (TRUST/baltik pipeline). Build with `make docs`; see the `trust-lime-docs` skill. |
| `compile_commands.json` | Platform-wide compiler flags (from trust-code). Flags are valid, but the database is not module-aware. |
| `.opencode/` | Agent configuration: commands, skill, scripts (this harness) |

## Build (baltik)

Always run from the repository root. The TRUST kernel must already be built.

| Command | Meaning |
|---|---|
| `make module_semi_optim` | **Default.** Rebuilds only this module, `-O3`, asserts on. Fast path. |
| `make module_optim` | Module, optimized. |
| `make module_debug` | Module, debug symbols / asserts (for gdb, valgrind). |
| `make optim` | Full build: kernel + module. Slow. |
| `make semi_optim` / `make debug` | Full build in that mode. |
| `make module_custom` | Module with `project.cfg` `cpp_flags`/`ld_flags` (see sanitizers below). |
| `make check_optim` / `make ctest_optim` | Baltik / ctest test suites (also `_semi_optim`, `_debug`). |
| `make help` | List every target. |

This machine is a 4-thread ThinkPad T430s with an HDD: builds are slow. Prefer
`module_*` targets and give the shell a generous timeout.

## Getting diagnostics fast

OpenCode V2 supports LSP, but it is deliberately disabled for this repo (see
`opencode.jsonc`): on this 4-thread HDD laptop, clangd would index the full
kernel. The fast path is the compiler directly; use it instead of waiting for a
full build:

```bash
bash .opencode/scripts/syntax-check.sh src/Pb_MHD.cpp
```

`/syntax <file>` wraps this. It reuses the real flags from
`compile_commands.json`, runs `g++ -fsyntax-only`, and finishes in seconds. Use
it after every meaningful edit, before a `/build`.

Two extra switches are available:
- `EXTRA_CXXFLAGS="-I/path"` appends flags (needed for the GoogleTest headers).
- `SYNTAX_CHECK_PRINT_FLAGS=1` prints the flags instead of compiling — this is
  how `unit-tests.sh` reuses exactly the same flags.

> **The recorded `compile_commands.json` is stale**: it says `-std=c++17`, but the
> kernel is really built with **`-std=c++20`** (see `trust-code/compile_TRUST_*_opt_*.log`),
> and the bundled Kokkos headers fail to parse under C++17. `syntax-check.sh`
> therefore forces `-std=c++20`. Keep that override if you touch the script.

## Compiler & style constraints

- **C++20**, `-mavx`, `-O3`, `-Werror` with `-Wall -Wextra -Wconversion -Wshadow
  -Woverloaded-virtual -Wnon-virtual-dtor -pedantic`. **Warnings are errors** —
  keep them at zero. `-Wconversion` is the usual trap (implicit `double`→`int`,
  sign mismatch).
- Kernel headers are included **with** the `.h` extension:
  `#include <Convection_Diffusion_Temperature.h>`.
- A `.clang-format` is provided, but automatic formatting on write is **off**
  (see `opencode.jsonc`); turn it on deliberately.

Full idioms (`Declare_instanciable`, `Param`, `REF(...)`, Doxygen mandates,
`// XD` tags, the class-extension recipe): **`trust-lime-coding` skill**.

## Extending the kernel from trust-LiMe

Reuse kernel base classes (e.g. subclass `Convection_Diffusion_Temperature`)
rather than reimplementing; see the recipe in the `trust-lime-coding` skill.
Kernel sources are available as the `trust-kernel` / `trust-include` references.

**`KERNEL_REUSE_NOTES.md` (repository root) is the accumulated knowledge base**:
kernel class choices, keyword-reading order, CL compatibility rules, the
`Champ_Inc_base` requirement for the transporting velocity, field factories, and
pointers to the exact kernel sources. Read it before extending the module, and
append new findings there.

## Sanitizers (local debugging)

`project.cfg` exposes `cpp_flags` / `ld_flags` (currently commented out). For a
local ASan/UBSan build, set:

```ini
cpp_flags : -fsanitize=address,undefined -fno-omit-frame-pointer -O1 -g -Wno-error
ld_flags  : -fsanitize=address,undefined
```

then `./configure && make module_custom`. Revert `project.cfg` before normal
builds. See the `trust-lime-coding` skill.
