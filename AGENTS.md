# AGENTS.md — trust-LiMe

TRUST-LiMe is a **baltik application**: a C++ module built on top of the CEA
[TRUST](https://github.com/cea-trust-platform) kernel. It adds a magnetic-field
convection–diffusion equation on top of the existing thermohydraulics, to model
coupled MHD. Kernel sources live in a sibling checkout (`../trust-code`); this
repository only contains the module.

## Repository layout

| Path | Purpose |

| `src/` | Module sources |
| `build/` | Generated by `./configure` (symlinks to `src/`, CMake files). Do not hand-edit. |

## Build (baltik)

Always run from the repository root. The TRUST kernel must already be built.

| Command | Meaning |
|---|---|
| `make module_semi_optim` | **Default.** Module only, `-O3`, asserts on. Fast path. |
| `make module_optim` / `module_debug` | Module, optimized / debug. |
| `make optim` / `semi_optim` / `debug` | Full build (kernel + module). Slow. |
| `make module_custom` | Module with `project.cfg` `cpp_flags`/`ld_flags` (sanitizers). |
| `make check_optim` / `ctest_optim` | Baltik / ctest suites (also `_semi_optim`, `_debug`). |
| `make help` | List every target. |

Hosts: laptop (T430s, 4 threads, HDD) is slowest; workstation (Ryzen 5 5600X,
SSD) faster. Both prefer `module_*` targets and generous timeouts. Toolchain:
OpenCode v2.0.28, Hermes v0.21.7 (workstation only), kernel built in
`../trust-code`.

Environment: source via `.opencode/scripts/with-trust-env.sh <cmd>` instead of
the four manual `source` lines (see `trust-lime-env`). Poll long builds with
`.opencode/scripts/wait-build.sh`.

Sanitizers: set in `project.cfg` (`cpp_flags`/`ld_flags` with
`-fsanitize=address,undefined ...`), then `./configure && make module_custom`;
revert `project.cfg` after. See `trust-lime-coding`.

## Getting diagnostics fast

OpenCode V2 LSP is disabled (clangd would index the ~25 MB kernel
`compile_commands.json`). Use the compiler directly:

```bash
bash .opencode/scripts/syntax-check.sh src/Pb_MHD.cpp
```

`/syntax <file>` wraps it. Use after every meaningful edit, before `/build`.
Switches: `EXTRA_CXXFLAGS="-I/path"` (GoogleTest headers),
`SYNTAX_CHECK_PRINT_FLAGS=1` (print flags; reused by `unit-tests.sh`).

> **`compile_commands.json` is stale**: it says `-std=c++17`, but the kernel
> builds with **`-std=c++20`** (see `trust-code/compile_TRUST_*_opt_*.log`);
> Kokkos headers fail under C++17. `syntax-check.sh` forces C++20 — keep that
> override.

## Agent setup (models)

| Agent/model | Use for |
|---|---|
| `build` (default) — `opencode/beam-free` (1M ctx) | Day-to-day editing/build |
| `@long` — `opencode/beam-free` | Large multi-file analysis |
| `@quick` — `opencode/deepseek-v4.1-flash-free` | Small questions |
| `/models` | Switch model for next message |

All free OpenCode Zen models; different model ids keep rate limits independent.
Verify any new model via a throwaway subagent run (direct `curl` is rejected
with `FreeTierError`). Do not re-add removed pins: `opencode/space-bunny-free`,
`opencode/ling-3.1-flash-free`, `opencode/flint-40b-free`,
`opencode/longcat-2.5-preview-free`.

Removed providers (`google`, `groq`, `openrouter`) are denied in global
`~/.config/opencode/opencode.jsonc`; re-enable by deleting a line from that
`policies` block.

Primary loop: `syntax-check.sh` → `make module_semi_optim` → validate.

## Parallel sessions (free-model budget)

All sessions share one OpenCode account. Serialize generation: one heavy session
plus at most one light one; stagger the rest. Use different models per session.
Keep `warming` off; keep Headroom proxy at `--mode cache` (do not switch to
`--mode token`). Nightly Hermes job runs on Gemini, not Zen.

## Hermes Agent (unattended runs)

Hermes (`~/.hermes`) drives OpenCode as a delegated worker. Project binding:
`hermes project show trust-lime`. Nightly job `trust-lime-arith-nightly`
(`7bd53fa53065`, `0 3 * * *`) runs `.opencode/scripts/unit-tests.sh
--arith-only`, delivers to `local`. Pin a working model on every run
(`--provider gemini --model gemini-3.1-flash-lite`). Emergency stop:
`hermes pause`.

## Validation (Jupyter)

Notebooks under `share/Validation/Rapports_automatiques/`, one form per notebook
at `<Category>/<FormName>/<FormName>.ipynb`, run in the TRUST Python env
(`venv_trust` + TRUST env), not the OpenCode venv. Use `/validate`; run
`/check-validation` first.

Rules (enforced by `check-validation.sh`): `.ipynb` at form root only; one form
per notebook (may run several scales); **all cases sequential** — no
`Decouper`/`Partitionneur`/`Scatter`/etc. in `.data`, no `partition()`, no
`nbProcs>1`. Parallel exception only for paths in `parallel_ok[]` (script is
source of truth), with the three comment-marker regions and `nbProcs=2` +
`case.partition()`.

## Compiler & style constraints

- **C++20**, `-mavx`, `-O3`, `-Werror` with `-Wall -Wextra -Wconversion
  -Wshadow -Woverloaded-virtual -Wnon-virtual-dtor -pedantic`. Warnings are
  errors. `-Wconversion` is the usual trap.
- Kernel headers included **with** `.h`: `#include
  <Convection_Diffusion_Temperature.h>`.
- `.clang-format` provided but auto-format on write is **off** (see
  `opencode.jsonc`).

Full idioms: `trust-lime-coding`.

## Extending the kernel

Reuse kernel base classes rather than reimplementing; recipe in
`trust-lime-coding`. Kernel sources available as `trust-kernel` /
`trust-include` references. Read `KERNEL_REUSE_NOTES.md` before extending;
append new findings there.

## Data file comment convention

Comments in `.data` files must use `# ... #` (spaces around content) or
`/* ... */`. TRUST data files are block-based; this keeps parsing consistent.
